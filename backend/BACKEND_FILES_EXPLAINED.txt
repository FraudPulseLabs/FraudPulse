================================================================================
BACKEND FILE GUIDE (simple overview)
================================================================================
Read this when you want to know what a file or folder is for. Paths are relative
to the "backend/" folder unless noted.

--------------------------------------------------------------------------------
ROOT (backend/)
--------------------------------------------------------------------------------

run.py
  Starts the web server in development (calls uvicorn on the FastAPI app).
  Run from this folder:  python run.py

requirements.txt
  Python packages the backend needs (FastAPI, SQLAlchemy, pandas, etc.).

pytest.ini
  Tells pytest where tests live and how to find modules (pythonpath, testpaths).

README.md
  Short human notes: how to run the API, DATABASE_URL, tests.

.gitignore
  Files Git should not track (often includes .env with secrets).

.env.example
  Template for environment variables. Copy to .env and fill in real values.

.env  (you create this locally; not in Git)
  Real secrets like DATABASE_URL for Supabase/Postgres.


--------------------------------------------------------------------------------
src/  — main application code
--------------------------------------------------------------------------------

src/main.py
  Creates the FastAPI "app", wires logging, mounts all API routes under /api/v1,
  and exposes GET /health.

src/config.py
  Small re-export of paths/settings so older code can still do:
  from src.config import DATA_DIR
  (ML scripts use this.)

src/__init__.py
  Marks src as a Python package (often empty).


--- src/core/  (settings and cross-cutting helpers) ---

src/core/config.py
  Loads .env, defines BASE_DIR, PROJECT_ROOT, DATA_DIR, reads DATABASE_URL,
  API prefix constant.

src/core/constants.py
  App name/version strings for the OpenAPI docs.

src/core/logging.py
  Basic logging setup for the process.

src/core/security.py
  Small security helpers (e.g. safe string compare, token helpers).

src/core/__init__.py
  Re-exports common config symbols for convenience.

src/api/__init__.py

src/api/v1/__init__.py

src/api/v1/transactions.py

src/api/v1/scoring.py

src/api/v1/decisions.py

src/api/v1/alerts.py

src/api/v1/cases.py

src/api/v1/profiles.py

src/api/v1/metrics.py
  Endpoint for dashboard-style metrics snapshot.

src/api/v1/admin.py
  Admin/settings style endpoints.

--- src/db/  (database connection and table shapes) ---

src/db/session.py
  Creates SQLAlchemy engine if DATABASE_URL is set; get_db() yields a session
  for dependency injection in routes (when you wire it up).

src/db/__init__.py
  Re-exports session helpers.

src/db/migrations/
  Placeholder folder for Alembic/SQL migration scripts (.gitkeep keeps the
  folder in Git). Your real schema may live in Supabase already.

src/db/models/base.py
  SQLAlchemy DeclarativeBase — shared parent for all ORM table classes.

src/db/models/__init__.py
  Imports all model classes so you can "from src.db.models import Transaction".

src/db/models/transaction.py
  ORM class for public.transactions (Supabase-aligned columns).

src/db/models/case.py, case_note.py, case_event.py
  ORM for cases and related notes/events.

src/db/models/fraud_score.py, score_reason.py
  ORM for scores and per-feature reasons.

src/db/models/alert.py
  ORM for alerts.

src/db/models/watchlist.py, watchlist_history.py
  ORM for watchlist and its history.

src/db/models/transaction_lifecycle.py
  ORM for status/history rows per transaction.

src/db/models/rule_trigger.py
  ORM for which rules fired on a transaction.

src/db/models/profile.py
  ORM for profiles (investigator/user style fields in your schema).

src/db/models/rejected_request.py

src/db/models/system_config.py
  ORM for key/value config (key is primary key in Supabase).

  ORM for audit events.


--- src/schemas/  (Pydantic: JSON shapes for validation/serialization) ---

API payloads. Used to validate incoming JSON and format outgoing JSON.

src/schemas/__init__.py
  Re-exports schema classes.

src/schemas/transaction.py, case.py, alert.py, ... (one per domain)
  Pydantic models aligned with your tables.

src/utils/__init__.py

FASTAPI — quick syntax notes (for beginners)
================================================================================

1) App object
   You create one FastAPI application:
     app = FastAPI()
   Uvicorn runs it: it listens on a port and passes HTTP requests to "app".

2) Routes (endpoints)
   A route ties a URL + HTTP method to a Python function.
   Example pattern in this project:
     @router.get("")
     async def list_items():
         return []
   - @router.get("")     → GET request
   - @router.post("")    → POST request
   - The path "" is relative to where the router is mounted.
     If the router is mounted at "/transactions", GET "" becomes GET "/transactions".

3) async def
   Route functions are often "async" so FastAPI can handle many requests
   efficiently. You can use regular "def" too for quick CPU-only work.

4) APIRouter
   Routers group related endpoints. In src/api/v1/__init__.py, many routers are
   combined into one big router, then included in main.py under prefix "/api/v1".

5) Return value = JSON
   If you return a dict or list from a route, FastAPI serializes it to JSON.
   If you return a Pydantic model, it becomes JSON using the model's fields.

6) Request body
   For POST, you can declare a body parameter with a type:
     async def create_item(body: dict): ...
   or use a Pydantic model for validation:
     async def create_item(item: ItemCreate): ...

7) Dependency injection (common next step)
   FastAPI can inject a database session:
     def get_db(): ...
     @router.get("/x")
     def read(db: Session = Depends(get_db)): ...
   "Depends" runs get_db per request and passes the result into your function.

8) Automatic docs
   With the app running, open:
     /docs   → Swagger UI
     /redoc  → ReDoc

9) Lifespan / startup
   main.py uses a "lifespan" context to run code when the server starts/stops
   (here: setup logging).

10) Where to look first
   - src/main.py          → app + /health + include_router
   - src/api/v1/*.py      → URL handlers
   - src/services/*.py    → logic those handlers call
   - src/db/models/*.py   → database table shapes
